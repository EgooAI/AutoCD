# 运行约定

## 短进程模型

AutoCD 不提供常驻 daemon 或 socket。交互菜单、单次检查、部署执行是同一个独立脚本的不同入口。每个进程完成工作即退出，跨次调用的信息保存在 SQLite。

自动调度采用 systemd：每个已开启项目各有一个 timer 和 oneshot 检查服务，命令为 `observe --id ID --scheduled`。间隔从 `.autocd.sh` 读取，下一次调用在上次检查结束后计时；`AccuracySec` 不超过 0.5 秒。独立服务隔离慢仓库的影响，检查进程有超时和项目检查锁。

满足条件时检查进程入队并尝试唤起独立 worker。worker 持有全局排他锁，只处理启动时的队列快照，结束即退出；新任务留待下次调用。另有 5 秒 worker timer 保证崩溃、唤起竞争或队列新增时不会永久遗留任务。没有部署时 worker 很快退出，不等待新任务。

没有 systemd 时可以执行 `tick [PATH]` 后执行 `worker`，或使用合并入口 `run-once [PATH]`。这些命令不自行重复运行；自动运行需要外部调度。`run-once` 的前台部署会占用当前终端，正式安装的检查和 worker 使用独立服务。

## 持久化与互斥

普通用户的数据在 `${XDG_DATA_HOME:-~/.local/share}/autocd`，root 在 `/var/lib/autocd`；`--home` 可指定独立实例。不同实例的 systemd 单元名包含数据目录的散列，互不覆盖。

| 路径 | 内容 |
| --- | --- |
| `state.sqlite3` | 监视开关、观察窗口、部署队列与历史；WAL 模式 |
| `schedule.json` | 定时任务开关、程序副本路径、单元名前缀 |
| `run/` | worker、各项目检查、安装操作的文件锁；兼容旧版的 daemon 锁 |
| `programs/` | 安装时保存的版本化单脚本 |
| `cache/`、`releases/` | 专用 Git 缓存、每次部署的独立检出 |
| `logs/` | 每次部署的日志和原始脚本快照 |

多个进程通过短 SQLite 事务原子更新状态。Git、Bash、systemctl 和交互等待期间不持有数据库写事务。监视设置包含递增修订号，慢检查在返回时必须匹配修订号，防止覆盖期间发生的暂停或重置。入队与任务领取也在事务中完成。

`State.open(paths)` 统一准备数据目录并管理数据库生命周期；状态层不依赖调度或服务管理。子进程继承的锁统一用文件描述符元组传递，服务安装与重启调度共用定时器激活和失败恢复流程。

worker 锁和原项目目录锁传给命令子进程；父进程被杀死后，旧命令仍在运行时不能重复部署。目录锁不产生工作区文件，还能防止两个不同数据目录的实例同时部署同一项目。使用支持 Linux flock 的本地文件系统。

## 冷静窗口

首次成功观察开始计时。候选 SHA、配置指纹、UTC 显示时间、单调时钟值和系统 boot ID 都持久化。使用包含休眠时长的 Linux CLOCK_BOOTTIME；正常进程退出不重置窗口，修改系统时间也不缩短冷静间隔，长时间休眠会被识别为观察空档。

SHA 或配置变化、网络错误、暂停再开启、停止调度、系统重启、超过 `2.5 × 监视间隔 + 1 秒` 的观察空档都会重新计时。菜单在记录过期时显示“等待新观察”，不继续显示失真的倒计时。

任务固定 SHA、配置指纹和监视修订号。出队及执行 Bash 前重新检查配置、远程和观察窗口，fetch 结果也必须匹配。命令开始后使用固定脚本快照完成本次任务；最终远程检查之后仍可能出现新提交，这是轮询模型的边界。

成功和失败记录均绑定 SHA 与配置指纹。配置变化允许重新部署相同 SHA；同一失败版本不自动重试。手动部署跳过冷静窗口，仍校验远程、配置及互斥状态。

## 生命周期与恢复

开启监视仅登记项目；自动执行还需要安装并开启定时任务。菜单关闭不会影响系统定时触发。暂停项目、删除配置或停止调度会取消相应排队任务，已经执行的 Bash 继续完成。全局停止调度保留各项目的监视偏好。

没有定时安装时，`deploy PATH` 会在当前进程执行；已安装并开启时唤起 oneshot worker。`--queue-only` 只入队。安装或更新必须显式执行 `schedule install`，日常打开新下载脚本不会替换已安装副本。更新时需等待当前部署完成；卸载保留数据。

只有取得空闲 worker 锁后才检查遗留的执行记录，未记录结果的任务标记为 unknown。每次检查不会把其他进程正在执行的任务误判为中断。操作员核实实际服务后使用 `resolve --outcome succeeded|failed` 记录结果。

旧版 schema 1 自动迁移到 schema 2，保留监视开关与部署历史，仅重置旧版无法跨进程复用的冷静窗口。旧 daemon 锁被占用时拒绝迁移；旧服务需先停止、卸载。数据库版本较新时拒绝读写，避免旧脚本破坏新结构。

## 部署脚本约定

脚本以一个 Bash 进程在独立发布目录运行，接收 `DEPLOY_SHA`、`PREVIOUS_SHA`、`RELEASE_DIR`、`PROJECT_DIR` 和 `AUTOCD_DEPLOYMENT_ID`。原工作区只提供配置，发布目录之外的数据由项目自行管理。

超时涵盖准备和执行，并终止进程组。长期服务应交给 systemd、容器等管理器；直接用 & 留下的子进程会被清理。退出码是成功判据，脚本应包含健康检查并自行处理回滚。子模块、LFS 和构建依赖由脚本显式获取；AutoCD 不自动删除历史发布目录。

运行用户提供 Git/SSH 凭据和部署权限，安装时保存 PATH。用户级定时任务要在注销后及开机运行，需管理员启用该用户的 systemd linger。日志可能包含脚本主动打印的敏感信息，数据目录仅允许运行用户访问。
